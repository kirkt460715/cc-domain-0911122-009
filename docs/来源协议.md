# Git 技术资料来源
python3 -m lab.git_source /tmp/manual-source 创建全新的本地发布副本和裸远端。main 依次经历建立、移动修改、合并和删除；conflict 分支包含同树重复 doc_id；rewritten 从初始提交分叉。采集入口可以使用返回的裸远端路径及 main，不能把发布者工作目录当作检查点。需要演练改写时，仅对这个临时裸仓库使用 git --git-dir=/tmp/manual-source/manuals.git update-ref refs/heads/main refs/heads/rewritten。
front matter 为 UTF-8 文档首行 --- 至下一 --- 中的单个 doc_id 键，值为 ASCII 标识，其余 Markdown 为正文。不要求完整 YAML。路径限制 manuals/，只接收普通 .md blob，符号链接和子模块明确不采。远端不包含生产凭据，不安装依赖或执行脚本。生成器构造文档历史，不执行 Corpus Gate 的采集操作。

# Corpus Gate 只读 Git 来源采集
采集器位于 corpus_gate/ingest/gitcollect/，只通过受限 git 子进程访问仓库，不引入第三方 Git 库。入口在登记时固定为获准的 remote_url、branch 与 path_scope，来源授权（sources）与文本画像（profiles）沿用既有登记，不另建凭据。

## 冻结优先
每次采集先把远端分支解析到的提交 OID 冻结到端点私有引用 refs/gate/<endpoint>/frozen，随后所有历史解释只认该冻结引用；远端在采集期间继续变化也不影响本轮。本地维护无工作区的裸镜像（clone --mirror / fetch --no-recurse-submodules），不签出内容。

## 身份与可见状态
文档身份取 front matter 的稳定 doc_id，路径仅记录为来源位置。同一提交树出现两个相同 doc_id 即报 git_doc_conflict：该提交记入 git_blocked_commits 并跳过，不产生任何文档版本，修复后的后续提交仍可继续采集。沿第一父提交顺序（root -> head）解释每棵树：新增/内容变化产生新版本，纯重命名延续版本并记录路径迁移，删除记为 withdrawn 来源撤回事件。合并提交保留全部父信息，但侧支临时版本不逐个重放，只在合并点按合并树导一次。

## 提交级确认与可恢复
一个提交的全部文档处理结果在同一事务内落库后才把该提交置为 confirmed；中途失败时最后一个 confirmed 提交即可恢复位置，git.checkpoint 报告确认范围与 blocked 提交。已有人工审查结论（review_events）与已发布语料（releases/release_members）维持原表原规则，Git 采集不写入 documents/intake/batches 流水线。

## 分叉与采集世代
远端分支回退或改写后，若旧 confirmed tip 不是新 HEAD 的祖先，采集停在 diverged：git.divergence 展示 merge-base 与两侧提交数，git.collect 被拒绝。只有操作员携带明确理由调用 git.reset_generation 才开启新世代；旧世代及全部版本证据归档保留，绝不自动清库重来。

## 只读与不执行
所有 git 调用固定参数数组、清理环境变量，并强制 core.hooksPath=/dev/null、关闭 fsmonitor/sshCommand/gitProxy/ext 协议与 LFS smudge；submodule 等动词在封装层禁用。符号链接、gitlink（子模块）、非 100644 模式与非 .md 条目录入 git_commit_excluded 但不采集，远端内容没有任何执行入口。
